# 첫 실행 설정 페이지 (WEB) — 11-12

## 왜 바꿨나

Portainer에 값을 자동으로 넣는 `portainer-bootstrap` 스크립트는 세 개의 관문에 걸렸다(모두 실제로 겪었다).

| 관문 | 증상 | 스크립트가 할 수 있는 일 |
|---|---|---|
| 헬스체크 | 그 이미지에 `wget`이 없어 unhealthy → `bosun`이 아예 안 뜸 | 헬스체크를 빼고 스크립트가 기동을 기다린다 |
| 초기화 제한 시간 | 첫 기동 5분 안에 관리자가 없으면 API가 303 `Redirect-Reason: AdminInitTimeout` | 5분 안에 돌아야 한다. 놓치면 `restart portainer`로 창을 다시 연다 |
| setup token | 미초기화 인스턴스는 `POST /api/users/admin/init`에 `X-Setup-Token` 헤더가 없으면 403 | 로그의 `setup_token=`을 복사해 넣어야 한다(자동화 불가) |

**바꾼 방식**: 화면이 첫 접속에서 필요한 값을 직접 받는다. 값은 **사용자가 직접 발급**한다. WEB은 값을 만들어 내지 않는다. Portainer 관리자 계정도 사용자가 Portainer 화면에서 만든다(WEB은 자격증명을 받지 않는다).

| 칸 | 어디서 받나 | 어디에 저장되나 |
|---|---|---|
| OpenRouter API 키 | openrouter.ai → Keys | `agent.env`의 `OPENROUTER_API_KEY` |
| Portainer 주소(Agent가 붙는 주소) | 이 스택 안이면 `https://portainer:9443` | `agent.env`의 `PORTAINER_URL` |
| Portainer API 키 | Portainer → My account → Access tokens | `agent.env`의 `PORTAINER_API_KEY` |

## 동작

- `GET /api/setup/status` — 세 값이 다 있는지, 화면에서 저장할 수 있는지(`AGENT_ENV_FILE`), 지금 값이 있는지, Agent 상태. **값 자체는 돌려주지 않는다**(설정 화면과 같은 규칙).
- `PUT /api/setup` — 보낸 값만 확인하고 저장한다. 이미 있는 값은 다시 넣지 않아도 된다.
  - OpenRouter: `GET https://openrouter.ai/api/v1/key` → 401이면 거부.
  - Portainer: `GET {url}/api/endpoints` (`X-API-Key`) → 401/403이면 키 문제, 연결 실패면 주소 문제, 200이어도 endpoint가 0이면 거부(docker_proxy가 쓸 대상이 없다).
  - 자체 서명 인증서면 검증을 끄고 한 번 더 본다(컨테이너 스택 기본값).
  - 하나라도 실패하면 **아무것도 저장하지 않고** 항목별 이유를 돌려준다(키 오타가 '설정됨'으로 남지 않게).
- 저장은 `agent.env`에 원자적으로 한다(임시 파일 → rename, 권한 600). 다른 줄·주석은 그대로 둔다.
- 저장 뒤 Agent를 다시 시작하고 준비될 때까지 기다린다(기본 30초, `SETUP_AGENT_WAIT_MS`). 준비 중이면 화면이 그 상태를 보여준다.
- 값이 하나라도 남아 있으면 저장이 됐더라도 설정 페이지에 머문다(빈 채로 대화를 시작하지 않게).

## 확인한 것 (실제 실행, 11-12)

서버를 띄우고 실제 응답으로 9가지 경우를 확인했다(스크립트: `/opt/data/cache/scratch/setup-test/run.sh`).

| # | 보낸 것 | 결과 |
|---|---|---|
| 1 | (아무 값 없음) | `200 {needsSetup:true, ...}` |
| 2 | 틀린 OpenRouter 키(진짜 openrouter.ai 호출) | `400` + "OpenRouter가 이 키를 거부했어요(401)…", **파일은 그대로** |
| 3 | 닿지 않는 Portainer 주소 | `400` + 주소를 확인하라는 안내 |
| 4 | 주소 형식 오류(`portainer`) | `400` |
| 5 | Portainer 스텁이 401(키 오타) | `400` + 키를 다시 만들라는 안내 |
| 6 | Portainer 스텁 200 + endpoint 1개 | `200` 저장 |
| 7 | 저장된 파일 | 권한 `-rw-------`, 기존 주석과 다른 줄(`SOME_OTHER=keep-me`) 보존 |
| 8 | 저장 뒤 상태 | Portainer 두 값 `set:true`, 모델 키만 남아 `needsSetup:true` |
| 9 | 빈 요청 | `400` + "저장할 값이 없어요" |

브라우저 확인(`npm run build:web` → 실제 백엔드): 첫 접속에 설정 페이지가 뜨고, 틀린 키는 그 칸 아래에 사유가 뜨며, Portainer 두 값을 저장하면 "이미 설정됨" 배지가 붙고 "아직 없는 값: OPENROUTER_API_KEY"로 머무르고, 세 값이 다 차면 채팅 화면이 뜬다.

## 남은 제약

- 웹에 로그인이 없다(`server/guard.ts`: Host/Origin 루프백 + 상태 변경 요청은 `X-Bosun: 1`). 3001을 루프백으로만 발행하므로 노출은 그 PC로 제한된다. 다른 PC에 열 계획이면 1회용 설정 토큰(기동 로그에 출력) 같은 장치를 먼저 붙여야 한다.
- 화면의 "Portainer 열기" 링크가 여는 주소는 설치할 때 정하는 WEB 환경변수(`PORTAINER_URL`)라 화면에서 바꾸지 못한다. 설정 페이지가 다루는 `PORTAINER_URL`은 **Agent가 붙는 주소**로, 다른 값일 수 있다(컨테이너 기본값: 브라우저 `https://localhost:9443`, Agent `https://portainer:9443`).
- 표준 CLI 경로(`portainer-bootstrap`)는 남겨 뒀다. 값을 만들지 않고 한 번에 끝내거나 화면을 쓰지 않는 설치에 쓴다.
