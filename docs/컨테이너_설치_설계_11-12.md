# BOSUN 컨테이너 설치 — 설계와 근거 (11-12)

목표: Portainer처럼 `docker compose up -d` 한 번으로 화면(웹)과 Agent, Portainer를 한 번에 띄워 제공한다.
결론: **가능하다.** BOSUN의 웹·Agent는 도커 소켓을 쓰지 않으므로(도커 조작은 모두 Portainer 경유) 컨테이너화를 막는 요소가 설계 단계에서 이미 제거돼 있다.

---

## 1. 왜 컨테이너화가 쉬운가

| 확인 | 근거 |
|---|---|
| 웹·Agent는 도커 소켓이 필요 없다 | 저장소 전체에서 `/var/run/docker.sock`이 나오는 곳은 `portainer/portainer-compose.yaml:7`(Portainer 자신)과 **소켓 마운트를 거부하는 정책 훅**(`ai-agent-hooks/tool_input_transform_stack_guard.py:29`, `tool_input_transform_direct_policy_guard.py:35`)뿐이다 |
| 웹 이미지가 이미 있다 | `Dockerfile` — `node:22-alpine` 2단계 빌드, `/data` 볼륨, `EXPOSE 3001`, 주석에 `AGENT_URL=http://agent:8080`(같은 compose) 전제 |
| Agent를 웹이 직접 띄울 수 있다 | `server/agentProcess.ts:34-42` — `AGENT_BIN`이 있으면 백엔드가 `docker-agent serve api <agent.yaml> --env-from-file <agent.env> --session-db <session.db> -l <listen> [--auth-token …]`을 자식 프로세스로 띄우고 관리 |
| 분리 구성도 가능 | `AGENT_BIN`을 비우면 `AGENT_URL`에 붙기만 한다(`server/agentProcess.ts:2-3`) |
| 호스트 설치 자동화 자산이 있다 | `test-push` 브랜치의 `scripts/bootstrap.sh`·`setup.sh` — 자리표시자 치환·검증 로직을 컨테이너 진입점에 재사용 |
| Portainer 자동 설정이 가능하다 | 관리자 생성 `POST /api/users/admin/init` → 로그인 `POST /api/auth`(JWT) → 키 발급 `POST /api/users/{id}/tokens`(JWT 필수) 응답 `{"rawAPIKey": "ptr_…"}` (Portainer 소스 `user_create_access_token.go` 확인) |
| 같은 네트워크면 TLS 문제가 사라진다 | Portainer CLI 기본값 `--bind :9000`(HTTP) / `--bind-https :9443`. 스택 안에서는 `http://portainer:9000`으로 붙어 자체 서명 CA(`SSL_CERT_FILE`) 설정이 불필요 |

참고: docker-agent에는 **공식 컨테이너 이미지가 없다**(설치 문서는 바이너리 릴리스·Homebrew·Docker Desktop 플러그인만 안내). 릴리스 바이너리를 이미지 빌드 시 내려받아 넣는다(Apache-2.0).

## 2. 구조

```
호스트                                  bosun 스택(compose 네트워크)
┌──────────────────────────────────────────────────────────────┐
│ 127.0.0.1:3001  →  [ bosun ]  화면(정적) + WEB 백엔드(node)    │
│                       └─ 자식 프로세스: docker-agent serve api  │
│                            └─ 훅(python3) → Portainer API      │
│ 127.0.0.1:9443  →  [ portainer ]  도커 소켓 보유(유일)          │
│                        ▲ http://portainer:9000 (스택 내부 HTTP)│
└──────────────────────────────────────────────────────────────┘
```

- 웹·Agent 컨테이너: 소켓 없음, `bosun_data`(agent.env·agent.yaml·session.db·backups.sqlite3), `bosun_web_data`(web.db)
- Portainer 컨테이너: 소켓 + `portainer_data`(기존 `portainer/portainer-compose.yaml`과 같은 볼륨 이름을 써서 통합 가능)

## 3. 추가한 파일

| 파일 | 역할 |
|---|---|
| `container/Dockerfile` | 웹+Agent **한 이미지**: node 22(Debian slim) + python3/pyyaml + docker-agent 릴리스 바이너리(v1.148.0) + `mcp-portainer`(pip 고정 설치) |
| `container/entrypoint.sh` | `agent.yaml` 자리표시자 치환(`/절대경로/`→훅 폴더, `/실행폴더/`→`/opt/bosun`), 잔여 자리표시자 검사, `agent.env` 시드, `AGENT_TOKEN` 생성, WEB 백엔드 실행 |
| `container/portainer-bootstrap.sh` | 최초 1회 자동 설정: 관리자 생성 → JWT → API 키 → `agent.env` 기록 |
| `container/.env.example` | 넣어야 할 값(모델 키, Portainer 관리자, 선택 값) |
| `docker-compose.yaml` | `bosun` + `portainer`, 볼륨·포트·헬스체크. 백업·soteria는 주석 예시 |
| `container/README.md` | 설치 절차, 확인 체크리스트, 실패 진단표 |

## 4. 자동화할 수 없는 것 (구조적 한계)

1. **백업 컨테이너는 앱이 생긴 뒤에만 만들 수 있다.** `backup/bosun-backup-compose.yaml`은 `bosun-data-1102` 같은 실제 앱 볼륨 이름을 `external: true`로 참조한다. 앱이 없으면 참조할 볼륨이 없다 → 앱 생성 시 Agent가 백업 스택을 만들거나(현재 정책 흐름), 설치 후 볼륨 이름을 적어 채운다.
2. **웹에는 로그인이 없다**(`README-web.md` 배포 절: "로그인이 없으므로 다른 PC에서 접속하게 열지 않는다") → 컨테이너에서도 `127.0.0.1:3001`로만 발행한다. 원격 제공은 인증 추가가 별도 스코프다.
3. **모델 API 키와 Portainer 관리자 비밀번호**는 사람이 넣어야 한다(값을 이미지에 넣지 않는다).

## 5. 함정과 대응 (구현에 반영)

| 함정 | 왜 | 대응 |
|---|---|---|
| `--env-from-file` 경로가 없으면 Agent가 즉시 종료 | 문서·실측: `Error: --env-from-file: open …` 후 종료, 화면에는 "연결 실패"로 보임 | 진입점이 `agent.env`를 항상 만들고(없을 때만) 빠진 키를 경고 |
| 자리표시자 치환 실패 → 훅이 전부 차단 | `AGENT_ENV_FILE` 경로가 어긋나면 `on_error: block` 훅이 모든 도구 호출을 막는다(fail-closed) | 치환 후 잔여 자리표시자(`/절대경로/`, `/실행폴더/`, `uvx`)가 있으면 생성 중단 |
| 훅의 `python3 -X utf8` | 이미지에 python3 없으면 훅이 실패해 조회까지 차단 | 이미지에 `python3` + `python3-yaml` 포함 |
| `uvx --from mcp-portainer==2.45.1` | 런타임에 네트워크·캐시 의존 | 이미지에 `mcp-portainer==2.45.1`을 pip 고정 설치하고 `command: mcp-portainer`로 치환 |
| Alpine base | docker-agent 릴리스 바이너리·파이썬 휠이 glibc 기준 | `node:22-bookworm-slim` 사용 |
| `AGENT_URL`의 호스트가 그대로 listen 주소가 된다 | `server/agentProcess.ts:38` | 한 컨테이너 구성에서는 `http://127.0.0.1:8080`(권장). 분리 시 에이전트를 `-l 0.0.0.0:8080`으로 직접 띄우고 웹의 `AGENT_BIN`을 비운다 |
| 기존 Portainer 스택과 9443 충돌 | 팀 `portainer-compose.yaml`은 `9443:9443`(전체 인터페이스) | 이 스택은 `127.0.0.1:9443:9443`. 기존 스택이 떠 있으면 Portainer 서비스를 빼고 `PORTAINER_URL_INTERNAL`만 맞춘다 |
| 웹 화면의 "Portainer 열기" 링크 | 브라우저가 여는 주소 ≠ 컨테이너 내부 주소 | `PORTAINER_URL`(브라우저용) 과 `PORTAINER_URL_INTERNAL`(컨테이너용) 을 분리 |
| `session.db`·`backups.sqlite3`·`web.db` 휘발 | 컨테이너 재생성 시 대화·승인 기록 소실 | `/opt/bosun`·`/data`를 볼륨으로 고정 |

## 7. 아직 검증하지 못한 것

도커 데몬이 없는 환경이라 **빌드·기동을 실제로 돌리지 못했다.** 아직은 사용자 PC에서 확인해야 한다.

- 이미지 빌드(릴리스 바이너리 다운로드 URL·arm64 포함), 이미지 크기
- 컨테이너 안에서 `mcp-portainer` 도구 목록이 정상인지(정책 훅·`permissions.allow`와 함께)
- 훅이 Portainer에 붙어 스택 검사·백업 가드가 동작하는지
- `docker compose`의 `depends_on: service_healthy` 순서와 Portainer 최초 설정 타이밍
- `PORTAINER_URL_INTERNAL=http://portainer:9000` 접근(문서상 기본값이나 실측 필요)
